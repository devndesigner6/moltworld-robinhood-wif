title: "Refunds and rebates"
description: "What happens when a Robinhood WIF chat request fails or uses less output."
---

## Current Robinhood policy

Robinhood production is chat-only. Chat is configured to settle after a successful answer, and the exact WIF amount is authorized for the request's `max_tokens` budget. Unused chat budget is **not** automatically rebated in WIF.

If a rare failure occurs after a WIF settlement has already been confirmed, it is marked for manual review. There is no automatic WIF refund worker.

## Requests that never settle

Some requests are never charged:

- Invalid bodies get `400` before any payment is requested.
- Unavailable or non-chat models are rejected before payment.
- A chat request that fails before successful completion is not settled.
- A payment challenge is not a payment; only the signed retry can authorize settlement.

## Legacy Algorand behavior

The isolated legacy Algorand deployment documented USDC chat rebates and on-chain refunds for upfront image, voice, and video work. Those rebates, refunds, and modalities are not enabled on the Robinhood WIF rail.
